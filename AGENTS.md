# SuperMetroidX agent guide

This file is the convention source for people and coding agents working in this repository.

## Product

SuperMetroidX is a static recompilation of the SNES game Super Metroid. The 65816 program is translated to C at build time. This repository owns the SNES runtime, the translator, and the desktop shell. It does not vendor `snesrecomp` or any other emulator tree.

The ROM, SRAM, save states, and generated translation of the ROM are user-supplied build inputs. Never commit them. Never commit a header, source file, or test fixture that contains ROM bytes. With `SMX_EMBED_ROM` (on by default) `smxembed` writes the ROM as C into `build/*/game/smx_rom.c`; that file and every build made from it contain the ROM and are never committed or published. Hashes of the game's output, such as `tests/game_hashes.h`, are not ROM bytes.

## Language

The runtime and the shell are C11. Do not add C++ translation units. The one exception to C is `packaging/android/SuperMetroidXActivity.java`, the subclass of SDL's Java activity that Android starts the game from; keep it that small.

`main` returns `int` because the C standard requires it. `argc` stays `int` for the same reason. Everywhere else, use SDL's explicit integer types: `Uint8`, `Uint16`, `Uint32`, `Uint64`, `Sint8`, `Sint16`, `Sint32`, and `Sint64`. Booleans are `bool`, `true`, and `false` as provided by the SDL3 headers. SDL3 renamed `SDL_bool`. Do not use `int`, `long`, `short`, `unsigned`, or `size_t` for project state. When an SDL or C API demands a different type, convert at the call boundary.

## Standard library

Use SDL3's C runtime wrappers from `SDL3/SDL.h` instead of the matching libc calls.

- Memory: `SDL_malloc`, `SDL_calloc`, `SDL_realloc`, `SDL_free`, `SDL_memset`, `SDL_memcpy`, `SDL_memmove`, `SDL_memcmp`
- Strings: `SDL_strlen`, `SDL_strcmp`, `SDL_strncmp`, `SDL_snprintf`, `SDL_strlcpy`, `SDL_strlcat`
- Files later in the project: `SDL_IOFromFile` and the `SDL_IOStream` API
- Logging: `SDL_Log`

Do not include `<stdio.h>`, `<stdlib.h>`, `<string.h>`, or `<stdint.h>` in project sources. SDL already provides the wrappers and the integer types.

## Dependencies

SDL3 is the platform layer: window, input, audio, threads, and filesystem. CMake pulls the pinned tag with FetchContent and builds it static (`SDL_STATIC` on, `SDL_SHARED` off). Link `SDL3::SDL3`.

OpenGL, when the shader presenter arrives, is the system OpenGL library reached through SDL's GL context. Shader sources live in the binary as `Uint8` arrays in headers. Do not ship loose `.glsl` files.

Do not add any third party libraries by default.

## Layout

- `include/smx/` — public headers, one module per header
- `src/` — implementations and the executable entry point
- `tests/` — one executable per module, registered with CTest
- `cmake/` — helper modules when a single `CMakeLists.txt` is no longer enough
- `packaging/` — templates for the packages' metadata: the macOS and iOS `Info.plist` files, the Android manifest and activity, the Windows resource script and manifest, the Linux desktop entry and AppStream metadata, and the players' `README.txt`. CMake fills them in from `project()`; icons are generated by `smxicon`, never committed as images
- `media/` — the README's trailer, `trailer.gif`: recorded footage of the game, never ROM data
- `.github/workflows/` — CI for Windows, macOS, and Linux

The executable target is `SuperMetroidX`. The static library target is `smx`. The translator CLI is `smxrecomp`, built on the `smx_translate_*` API in `include/smx/translate.h`. `smxicon` writes the icon that `smx_icon_*` (`include/smx/icon.h`) draws as the packages' `.icns`, `.ico`, and PNG files. `smxsave` writes play-test saves through the `smx_save_*` API in `include/smx/save.h`; `playtest.sh` wraps it. CMake runs it on `SMX_ROM` (default `SuperMetroid.sfc` at the repository root) and links the generated `smx_game` library into the shell. With `SMX_EMBED_ROM` it also links the ROM itself, written as C by `smxembed`, as `smx_game_rom` (`src/rom_stub.c` defines it as NULL otherwise). Without a ROM the shell links `src/game_stub.c` and interprets.

## Build

CMake is the build description. The Makefile is the interface on macOS, Linux, and MSYS2; `build.bat` provides the same common commands in native Windows shells.

- `make build` — Debug: no optimization, debug symbols
- `make release` — optimized, `NDEBUG`
- `make play` — Release build, then run it on `ROM` with extra `ARGS`
- `make run` — Debug build, then run it on `ROM` (default `SuperMetroid.sfc`) with extra `ARGS`
- `make debug` — the same under lldb on macOS or gdb on Linux, printing every thread's backtrace on a crash
- `make test` — Debug build, then CTest; with a ROM it also runs the tests labelled `rom`
- `make test-release` — Release build, then CTest
- `make fmt` — `clang-format` on tracked C and headers
- `make docs` — Doxygen HTML under `docs/html`
- `make clean` — delete `build/` and `docs/html`
- `make package` (or `make dist`) — Release build, tests, and a CPack package in `build/release/dist`: a `.dmg` of the app bundle, a `.zip` of the `.exe`, or a `.tar.gz` in the Linux `bin/` and `share/` layout
- `build.bat <command>` — native Windows equivalents for `build`, `release`, `play`, `run`, `test`, `test-release`, `package`/`dist`, and `clean`; optional settings use the same `CMAKE_ARGS`, `CTEST_ARGS`, `ROM`, and `ARGS` environment variables
- `make xcode` — macOS: an Xcode project in `build/xcode`, opened in Xcode, to build, run, debug, sign, and archive the app; it signs for the team of a signing certificate in the keychain (`cmake/AppleTeam.cmake`), or `TEAM=<team ID>`. Its settings come from `CMakeLists.txt`, never from edits to the generated project
- `make ios` — the same for iPhone and iPad in `build/ios`. A cross build (`CMAKE_CROSSCOMPILING`) imports `smxrecomp`, `smxembed`, and `smxicon` from `SMX_HOST_TOOLS` (the Release build) and has no tests or package
- `make android` — a Release cross build with the NDK in `build/android`: the game as `libmain.so`, packed into `SuperMetroidX.apk` with SDL's Java activity by the SDK's own tools (`cmake/AndroidApk.cmake`; no Gradle), signed with the SDK's debug key. It takes the SDK from `ANDROID_SDK` (default `~/Library/Android/sdk` or `~/Android/Sdk`), its newest NDK, one `ANDROID_ABI` (default `arm64-v8a`), and a JDK 17 when there is one, because the d8 of build-tools before 35 can't read classes from javac 21 or later
- `make android-run` — install the APK on the connected device or running emulator, starting the first virtual device (or `AVD`) when there is neither, and open the game

Generated files stay under `build/`. Do not commit them. That includes `build/*/game/`, the translation of the ROM, and its `trace.txt`.

## Style

`.clang-format` is authoritative. Run `make fmt` before committing.

Name functions `smx_<module>_<verb>`. Name types `Smx<Name>` if a struct is part of the public API. Keep headers self-contained and wrapped in `#ifndef SMX_<NAME>_H_`.

Comment a function when the constraint is not obvious from its name. Do not comment the control flow.

## CI

GitHub Actions builds and tests Debug on `ubuntu-latest`, `macos-latest`, and `windows-latest` with `SMX_EMBED_ROM=OFF` and no ROM. The `raspberry-pi (ROM)` job runs on the owner's self-hosted Raspberry Pi with the ROM built in, and runs `make test` and `make test-release` with the `rom` tests. All four are required to merge. Jobs run only in `bluesentinelsec/SuperMetroidX` and never for forks or pull requests from forks; keep that guard on every job. A change that does not pass `make test` and `SuperMetroidX --smoke` with `SDL_VIDEODRIVER=dummy` is not done.

## What comes next

The SNES runtime (CPU bus, PPU, APU, DMA, HDMA) is written here, in C, against frame hashes from an NTSC reference log. The translator emits C that calls the same cycle-timed CPU operations as the interpreter, so translated and interpreted runs produce identical frames; `tests/test_translate.c` checks every opcode under every flag set against the interpreter. The shell presents the picture through an OpenGL 3.2 core context (`smx_present_*` in `include/smx/present.h`), with its shaders as `Uint8` arrays in `src/present_shaders.h`, and falls back to an SDL renderer without OpenGL. iOS, which has only OpenGL ES, always uses the renderer: SDL's GPU renderer with a Metal Shading Language copy of the scanline shader, embedded as source like the GLSL and compiled when the game starts (`SDL_CreateGPURenderState`), or any renderer without scanlines. Android, which also has only OpenGL ES, uses SDL's OpenGL ES renderer without scanlines, plays in landscape, and takes the Back button to open and close the cheats menu. Phones and tablets (`SMX_SHELL_TOUCH` in `src/main.c`, iOS and Android) draw a Super Famicom controller over the window through the presenter's `draw` hook (`smx_touch_*`, `include/smx/touch.h`) and replace the settings menu with a cheats-only menu of switches (`smx_touchmenu_*`); desktop builds have neither. Cheats (`smx_cheat_*` in `include/smx/cheat.h`, `--cheats` and keys 1-5) write Super Metroid's RAM between frames, as a cheat cartridge would, and copy what they draw (HUD icons, suit colors, the hyper beam's palette effect) from the game's own ROM tables; short messages are drawn on a copy of the picture with SDL's debug font (`smx_overlay_*`). Turbo (`SmxCheats.turbo`, the menu or key 6) runs the console's frames 1.5 to 4 times as fast and plays the sound at that rate through `smx_sound_set_speed`; it writes nothing. Holding any button through the intro skips it (`smx_skip_*` in `include/smx/skip.h`) by handing it to the routine its own last scene ends with, which saves the new game as the whole intro would. The settings menu (`smx_menu_*`, opened with `~` or R3) changes `SmxSettings` (`smx_settings_*`, saved as `settings.ini` in the save folder, under command-line options) and the cheats while the game is paused; every play-facing command-line option belongs in it. Sound goes out through `smx_sound_*` (`include/smx/sound.h`): the S-DSP can mix what the listener hears from a sinc or cubic interpolation of the same voices (`SmxDsp.heard`) while everything the SPC700 sees stays Gaussian, and `smx_resample_*` converts 32040 Hz to the device's rate. The version lives in `project()` in `CMakeLists.txt`, with `SMX_RELEASE_DATE` beside it for the AppStream release entry; change both together. It maps an Xbox-style gamepad and the keyboard through SDL, keeps SRAM in the OS user-data directory, and keeps save states independent of SRAM. Display enhancements (fill scaling, the 8:7 television aspect, scanlines) default on and each has a command-line switch to turn it off; release builds start borderless fullscreen and debug builds windowed.

Version 1.0 plays the whole game. Later releases add modern features on top of it without changing what the runtime emulates.
